# T1. 무료 데이터 출처 조사 (v0.2)

> 조사일 2026-10-07 · 조건: **유료 API 사용 안 함**, 링크는 웹페이지 크롤링, 캡쳐는 OCR.
> 사실(출처 있음)과 추론(⚠️)을 구분했습니다.

## 1. 결론 요약
| 정보 | 1순위 | 2순위 | 비고 |
|---|---|---|---|
| 이름·주소·좌표·전화·카테고리 | 링크 크롤링(플레이스 페이지) | 캡쳐 OCR | v0.1 에서 구현 |
| **영업시간·휴무·브레이크** | **캡쳐 OCR (정보 탭/홈 탭)** | 링크 크롤링 | 플레이스 상세는 동적 로딩이라 크롤링이 불안정 ⚠️ |
| **메뉴·가격** | **캡쳐 OCR (메뉴 탭)** | 블로그 본문 | |
| 평점·리뷰 수 | 캡쳐 OCR (홈 상단) | 크롤링 | 원문 리뷰는 저장하지 않고 수치·키워드만 |
| 편의(주차·단체·와이파이) | 캡쳐 OCR (홈 하단 편의 줄) | 블로그 | |
| 가까운 역·도보거리 | 캡쳐 OCR ("○○역 5번 출구에서 534m") | 좌표 기반 추정 | |
| 이동 시간 | **직선거리 × 우회계수 ÷ 수단별 속도 (추정)** | — | 무료·무키. 결과에 "추정" 표시 |
| 머무는 시간 | 카테고리 기본값 | 본문("2시간 소요") | |

→ **캡쳐 OCR 이 주 경로**, 링크 크롤링은 보조로 설계합니다.

## 2. 링크 크롤링

### 지켜야 할 것
- **robots.txt 를 확인하고, 금지된 경로는 요청하지 않습니다.** 예: 카카오맵 장소 상세 JSON(`place.map.kakao.com/main/v/…`)은 robots.txt 가 막고 있어 요청이 거부됐습니다(이번 조사에서 직접 확인).
- 같은 호스트에 초당 1회 이하로 요청하고, 결과를 캐시합니다. 로그인·인증 우회는 하지 않습니다.
- 서비스 약관상 대량 수집은 금지일 수 있습니다. **사용자가 직접 저장한 링크 1건을 그때그때 읽는 용도**로만 씁니다.

## 3. 캡쳐 OCR (Tesseract, 무료·로컬)
- 한국어 언어 데이터(`kor`)가 필요합니다. macOS: `brew install tesseract tesseract-lang`.
- **실측**: 사용자가 보낸 네이버 플레이스 홈 화면 캡쳐(753×2000)를 `kor+eng`, `--psm 4` 로 읽었을 때 정확도는 아래와 같았습니다.
  - 정확: 상호명, "일식당 · 4.88 · 리뷰 539", "17:00에 영업 시작", 주소(호수 "201호"→"2018" 오인식), 역·출구·거리, 전화(0507-…), 예약 링크(catchtable), 편의 줄
  - 깨짐: 사진 위 글자·아이콘 주변, 탭 이름 일부
  - → 플레이스 화면은 **줄 단위 규칙 파서**로 대부분 구조화 가능. 영업시간은 홈 탭에 "오늘 시작 시간"만 보이는 경우가 많아 **정보 탭(요일별 시간) 캡쳐를 같이 받는 흐름**이 필요합니다.
- 비전 LLM(선택)은 OCR 대신 이미지를 직접 읽습니다. 유료 데이터 API 는 아니지만 사용량 과금이 있으니 선택 사항으로 둡니다.

## 4. 이동 시간 (무료·무키)
- 직선거리(haversine) × 우회계수 1.3 ÷ 수단별 평균 속도 + 고정 시간(대기·주차)
  - 도보 4.5km/h · 자전거 12km/h · 대중교통 18km/h + 대기 8분 · 자가용 22km/h + 주차 7분 (도심 기준 ⚠️ 추정치)
  - 700m 이내는 수단과 관계없이 도보로 계산
- 공개 경로 서버(OSRM 데모 등)는 이용 정책상 서비스 트래픽에 쓰기 어렵고, 대중교통 경로는 무료 무키 API 가 없음 → **추정치 + "추정" 라벨**, 실제 길찾기 연동은 인터페이스만 열어 둠.
